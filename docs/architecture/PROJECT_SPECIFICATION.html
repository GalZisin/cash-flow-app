📋 סקירה כללית - Overview

🎯 מטרת המערכת

מערכת לניהול תזרים מזומנים אישי/משפחתי, בעברית קודם (RTL) ובאנגלית. מעקב אחר הכנסות, הוצאות, פריסות תשלומים והלוואות, השקעות, תקציב ויעדים פיננסיים, עם סימולציה לבדיקת השפעת יעדים לפני שמחליטים ועם יועץ AI שמקבל סיכום פיננסי מחושב של הנתונים.

👥 משתמשי קצה
  • משתמש יחיד שמריץ את האפליקציה על המחשב שלו (אין אימות משתמשים)
  • משפחות המתכננות רכישות גדולות, הלוואות ושיפוצים
  • מי שרוצה תחזית לשנים קדימה ולא רק מעקב על העבר
  • דוברי עברית ואנגלית (החלפת שפה וכיוון בלחיצה)
✨ יכולות מרכזיות
  • טבלת תזרים חודשית עם חישוב יתרות, צביעת שורות וברירות מחדל לחודש חדש
  • ייצוא ל-Excel ודוח PDF לטווח חודשים עם גרפי סיכום
  • פריסות, הלוואות ופעימות: התקדמות אוטומטית לפי מועד החיוב, עם תיקונים ידניים
  • השקעות: עסקאות, צילומי שווי, תשואה (CAGR, XIRR) וסימולציה
  • מעקב תקציב לפי קטגוריה עם התראות חריגה
  • יעדים פיננסיים עם ניתוח היתכנות וסימולציה נפרדת שלא משנה את התזרים
  • יועץ AI: צ'אט בזרימה, ניתוח, סימולטור תרחישים, דאשבורד עם גרפי מגמות ותובנות, ארכיון
  • 6 ערכות צבע, כל אחת במצב בהיר וכהה

🏗️ ארכיטקטורה - Architecture

📐 מבנה האפליקציה

שלוש שכבות שמדברות רק דרך ממשקים מוגדרים: לקוח Angular (פורט 4300 בפיתוח), שרת Express (פורט 3000, מגיש גם את הלקוח הבנוי מ-dist/), ו-SQL Server (מסד CashFlowDB). הלקוח לא ניגש למסד ולא למודל השפה; הכל עובר דרך השרת. תרשים אינטראקטיבי: ARCHITECTURE_DIAGRAM.html בשורש הפרויקט.

🎨 Frontend (Angular 21)
  • Standalone Components, 6 מסכים ב-lazy loading
  • State ב-signals (signal / computed), toObservable רק לצרכני rxjs
  • inject() ל-DI, OnPush בקומפוננטות תצוגה
  • Reactive Forms בלבד, @if / @for
  • Angular Material + Bootstrap 5, ngx-translate (he / en)
  • ערכות צבע דרך tokens (var(--cf-*)), בלי צבעים קשיחים ב-SCSS
⚙️ Backend (Node 24 + Express 5)
  • routes (ולידציה) → services (לוגיקה) → repositories (SQL בלבד)
  • SQL Server דרך mssql + msnodesqlv8, פרמטרים מוקלדים
  • שגיאות מוקלדות + error middleware עם מעטפת אחידה
  • logger לקבצים + טבלת לוג גישה ל-API
  • CORS מוגבל, גבול גוף בקשה, rate limit לנתיבי AI
  • מודול AI עם ספק מתחלף: Groq (ברירת מחדל) או Ollama

📊 מודלי נתונים - Data Models

💰 MonthData - נתוני חודש בתזרים
interface MonthData {
  month: string;                 // תאריך החודש (ISO)
  startingBalance: number;       // יתרת פתיחה
  income: number;                // הכנסה
  mortgagePayment?: number;      // משכנתא
  loanPayment?: number;          // הלוואות (ידני + אוטומטי מהפריסות)
  installmentsPayment?: number;  // פריסות, מחושב מ-InstallmentService
  additionalIncomes?: { description: string; amount: number }[];
  regularExpenses?: ExpenseItem[];  // הוצאות שוטפות
  specialExpenses?: ExpenseItem[];  // הוצאות מיוחדות
  endingBalance: number;         // יתרת סגירה
  savings?: number;
  rowColor?: string | null;      // צבע שורה שבוחר המשתמש (ירוק / צהוב / אדום)
}
🏷️ ExpenseItem - פריט הוצאה
interface ExpenseItem {
  description: string;
  amount: number;
  category: ExpenseCategory;
  goalRelated?: boolean;         // ההוצאה נוספה מיעד (בסימולציה)
  goalId?: string;
}

enum ExpenseCategory {           // ערך לא מוכר מנורמל ל-OTHER
  FOOD, DINING_OUT, CAR, HOME, HOME_IMPROVEMENT, FURNITURE, APPLIANCES,
  VACATION, ENTERTAINMENT, GIFTS, HEALTH, PROFESSIONAL, INVESTMENTS,
  EDUCATION, SHOPPING, OTHER
}
💳 Installment - פריסת תשלומים
interface Installment {
  id: string;
  name: string;
  totalAmount: number;
  downPayment: number;
  monthlyPayment: number;
  installmentsCount: number;
  startDate: string;              // YYYY-MM או YYYY-MM-DD
  color: string;
  notes: string;
  paymentType?: 'manual' | 'loan' | 'milestone';
  loanComponents: LoanComponent[];   // הלוואות: החזר, ריבית, פירעון מוקדם
  milestones?: Milestone[];          // פעימות לפי אחוזים
  paymentOverrides?: PaymentOverride[];  // תיקונים ללוח האוטומטי
  linkedGoalId?: string;
  // תאימות לנתונים ישנים, לא משפיעים על ההתקדמות:
  manualPaidCount: number; payments?: ...; milestonePayments?: ...;
}

interface PaymentOverride {
  key: string;      // 'down' | 'm:<n>' | 'l:<loanId>:<n>' | 'l:<loanId>:payoff' | 'ms:<id>' | 'x:<id>'
  status: 'paid' | 'skipped';
  date?: string;    // YYYY-MM-DD
  amount?: number;
  description?: string;
}
📈 Investment - השקעה
interface Investment {
  id: string;
  name: string;
  type: 'pension' | 'fund' | 'stock' | 'other';
  transactions: { id?: string; date: string; amount: number; type: 'deposit' | 'withdraw' }[];
  snapshots: { id?: string; date: string; value: number }[];   // צילומי שווי
  initialValue?: number;
  annualReturn?: number;
  simulationRules?: SimulationRule[];   // הפקדות חודשיות / חד-פעמיות לפי טווח חודשים
}
🎯 FinancialGoal - יעד פיננסי
interface FinancialGoal {
  id: string;
  name: string;
  description?: string;
  type: 'PURCHASE' | 'LOAN_PAYOFF' | 'SAVINGS' | 'PROJECT';
  targetAmount: number;
  targetDate: string;              // YYYY-MM
  loanDetails?: LoanDetails;
  schedule?: { type: 'single' | 'loan' | 'milestone'; amount?; date?; loan?; milestones? };
  linkedInstallmentId?: string;
  priority: number;                // 1 = הכי חשוב
  isFixed?: boolean;               // יעד שלא זז בתרחיש
  analysis?: GoalAnalysis;         // status: ACHIEVABLE | WARNING | NOT_ACHIEVABLE,
                                   // projectedBalance, monthlySavingsNeeded, suggestedDate,
                                   // reasons[], recommendations[], conflicts[] ...
  completed: boolean;
  createdDate: string;
  updatedDate: string;
}

🎯 פיצ'רים - Features

💰 תזרים מזומנים
  • טבלה חודשית עם חישוב יתרת סגירה אוטומטי
  • הכנסות נוספות, הוצאות שוטפות ומיוחדות עם קטגוריות
  • פריסות והלוואות נכנסות אוטומטית מהמסך שלהן
  • ברירות מחדל לחודש חדש
  • צביעת שורה ירוק / צהוב / אדום (ירוק = שורה מצומצמת)
  • שמירה דיפרנציאלית: רק חודשים שהשתנו נכתבים
  • ייצוא Excel (שני גיליונות) ודוח PDF לטווח חודשים
💳 פריסות והלוואות
  • שלושה סוגים: תשלומים קבועים / הלוואה / פעימות
  • תשלום נחשב שולם כשמועד החיוב שלו הגיע
  • תיקון ידני: שולם מוקדם, בסכום אחר, או "לא שולם"
  • פירעון מוקדם של הלוואה, תשלום נוסף שלא בלוח
  • התראה אם פריסה חדשה מורידה את היתרה מתחת לסף
  • אותו כלל בלקוח ובשרת (סיכום ה-AI)
📈 השקעות
  • הפקדות ומשיכות, צילומי שווי לאורך זמן
  • שינוי באחוזים, CAGR, XIRR כולל ולפי שנה
  • סימולציית צמיחה עם חוקי הפקדה לפי טווח חודשים
  • סוגים: פנסיה, קרן, מניה, אחר
💵 מעקב תקציב
  • תקרה חודשית לכל אחת מ-16 הקטגוריות
  • ההוצאה בפועל מחושבת מהתזרים של החודש
  • התראות: warning ב-90-100%, danger מעל 100%
  • מגמה לעומת חודשים קודמים
🎯 יעדים וסימולציה
  • יעדי רכישה / פירעון הלוואה / חיסכון / פרויקט
  • תשלום חד-פעמי, הלוואה או פעימות
  • ניתוח היתכנות, תאריך מוצע, התנגשויות בין יעדים
  • ניתוח מחדש של כל היעדים אחרי כל שמירת תזרים
  • טבלת סימולציה נפרדת; התזרים המקורי לא משתנה
🤖 יועץ AI
  • צ'אט עם תשובה בזרימה (streaming) ושמירת שיחות
  • ניתוח מלא וסימולטור "מה אם" לתרחיש
  • דאשבורד: סקירה כללית (KPI, תובנות AI, גרפי מגמות ותחזית), תרשים זרימה, תרשים הוצאות
  • ארכיון דוחות (ניתוח, תרחיש, תובנות) עם סינון
  • תשובה בעברית או באנגלית
🎨 ממשק
  • עברית (RTL) ואנגלית (LTR), החלפה בלחיצה
  • 6 ערכות צבע (קלאסי, אוקיינוס, אמרלד, סגול, שקיעה, גרפיט) × בהיר / כהה
  • אנימציות GSAP (3 דירקטיבות)
  • פריסה רספונסיבית למחשב, טאבלט ונייד
🆕 פיצ'ר מיוחד: מערכת סימולציה. במסך היעדים יש טבלת תזרים נפרדת (isSimulation). CashFlowSimulationService משכפל את התזרים המקורי ומוסיף לו את ההוצאות של היעדים, כך שרואים את ההשפעה לפני שמחליטים. התזרים המקורי לעולם לא משתנה מהיעדים. "רענן מתזרים מקורי" (אחרי אישור) מוחק את כל היעדים וטוען מחדש את המקור.

🔄 תהליך עבודה טיפוסי: טעינת התזרים
// 1. הקומפוננטה מבקשת מהשירות
this.cashFlowService.load().subscribe();          // השירות מעדכן signal של החודשים

// 2. השירות שולח HTTP
this.http.get<CashFlowData>(`${environment.apiUrl}/cash-flow`)

// 3. route → service → repository
router.get('/cash-flow', asyncHandler(async (req, res) => res.json(await cashFlowService.getCashFlow())));

// 4. repository מריץ SQL עם פרמטרים מוקלדים (db/helpers.js) וממפה שורות (db/mappers.js)

// 5. שגיאה בכל שכבה → errorHandler → { success:false, error:{ name, message, code? } }
🔍 לוג גישה ל-API: כל service ו-repository מיוצא דרך utils/traceMethods.js, שרושם כל קריאה ב-request context. middleware/apiAccessLog.js כותב שורה אחת לכל בקשת /api ל-log.cash_flow_api_access: request, response, שגיאה, זמנים ו-inner_method_name עם שרשרת המתודות.

🔄 תהליכים - Process Flows

💾 שמירת תזרים

1. המשתמש לוחץ "שמור"
CashFlowTableComponent → CashFlowService.save()
⬇️
2. POST /api/cash-flow
cashFlow.routes → cashFlow.service (נורמליזציה)
⬇️
3. כתיבה דיפרנציאלית
cashFlow.repository.write() + db/cashFlowDiff.js: רק חודשים שהשתנו, בטרנזקציה אחת
⬇️
4. ניתוח יעדים
goals.service.analyzeAllGoals(): טעינה אחת, ניתוח בזיכרון, כתיבה אחת
⬇️
5. תשובה + עדכון UI
{ success: true }, תג "נשמר לאחרונה", ה-cache של הסיכום מתאפס

🤖 שאלה ליועץ ה-AI

1. AiService.chatStream(question)
fetch עם קריאת הזרם
⬇️ POST /api/ai/chat-stream (rate limit)
2. financialSummary.getSummary()
מה-cache, או בנייה מחדש ב-cashflow-engine מהמסד
⬇️
3. ai.service.getChatStream()
prompt = סיכום + שאלה → Groq (או Ollama)
⬇️
4. טוקנים זורמים חזרה
chunked text/plain. מודל לא זמין → 503 AI_UNAVAILABLE

🎯 יעד חדש וסימולציה

1. טופס יעד
GoalsComponent → GoalsService.create()
⬇️ POST /api/goals
2. שמירה וניתוח
goals.repository.create() → analyzeAllGoals() → 201 עם היעד המנותח
⬇️
3. הסימולציה מתעדכנת
CashFlowSimulationService (combineLatest על התזרים והיעדים) משכפל את התזרים ומוסיף את הוצאות היעדים
⬇️
4. טבלת הסימולציה
CashFlowTableComponent (isSimulation=true). התזרים המקורי לא משתנה

  • אימות משתמשים (היום: משתמש יחיד, מקומי)
